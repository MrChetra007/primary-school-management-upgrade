> Use this document as the single source of truth to generate the full project.
> Stack: Vue 3 + Vite + Tailwind CSS v4 + Supabase (PostgreSQL)
> Target: Cambodian primary schools
> Schema Version: v10 (roadmap v16)

## 1. Project Overview

A multi-tenant school management system for Cambodian primary schools. Roles: Super Admin (platform-level), Admin/Director (school-level), Teacher, Librarian, and Parent (anon, link-only portal).

**Core feature areas:**
- Multi-tenant: each school is isolated via `school_id` on every table
- Student management with batch Excel import/export
- Monthly & semester score entry with auto-calculated averages, ranks, grades
- Daily student attendance (bulk mark by date)
- Teacher check-in (once per day, auto-calc present/late)
- Library (books + borrows)
- Budget & inventory tracking
- Health/growth/vaccination/sick-day records
- Honor board & certificate designer (drag-drop text on templates)
- Report card PDF generation
- **Parent portal**: link-only access (no login) — teacher generates a UUID link per class per month/semester
- **Report link approval flow**: teacher requests → admin approves/rejects → link unlocks
- **In-app notifications**: bell icon with realtime updates
- **Teacher phrase library**: personal reusable feedback chips
- **PWA**: install prompt, service worker, offline cache

## 4. Key Design Decisions

### 4.1 Every User IS a Teacher
In Cambodian schools, all staff members are teachers. The librarian is a teacher who manages the library. The admin/director is a teacher who runs the school.
- Every user account always has a matching `teachers` row
- `users.role` only controls **what they can access** — not who they are
- `teachers.user_id` is `NOT NULL UNIQUE` — one profile per account

### 4.2 Multi-Tenant via school_id
- Every table has `school_id` referencing `schools(id)`
- RLS policies auto-scope using `get_user_school_id()` helper
- `super_admin` role bypasses school scoping — sees all schools
- `school_id` is set via `DEFAULT get_user_school_id()` on all tables

### 4.3 Parent Portal: Link-Only Entry
- Parents do NOT log in. They access via a UUID link: `/parent/report/:report_link_id`
- Link is generated by teacher per class per month/semester
- Parent selects their child from a dropdown of students in that class
- Report card shows scores + attendance for that period only
- Health/growth/vaccinations/sick days are **never** exposed to anon
- Anon RLS is scoped to report link context — no open `using (true)` policies

### 4.4 Report Link Approval Flow
- Teacher clicks "Send for Approval" → `report_links.status` = `'pending'`
- Admin receives notification → approves or rejects (with optional note)
- Teacher notified of decision → if approved, copy-link button unlocks
- Teacher writes per-student notes before sending for approval
- **Only approved links** are visible to anon parents

### 4.5 Subjects Per-Class (not Global)
- `class_subjects` junction table links subjects to specific classes
- Grade 1-3: no English. Grade 4-6: includes English
- Score entry fetches subjects from `class_subjects`, not global `subjects`

### 4.6 Score Calculation on Frontend
- DB stores raw scores only
- `scoreCalculator.js` computes monthly averages, semester averages, ranks
- Competition ranking: ties share rank, next rank skips (1,1,3,4,5,6,6,8)

## 7. Auth Flow

### Startup (main.js):
1. Create Vue app, install Pinia + Router
2. Mount app
3. Register Supabase `onAuthStateChange` listener (EXACTLY ONCE)
4. Listener calls `auth.handleAuthEvent(event, session)`

### Pinia Auth Store (`src/stores/auth.js`):
- `init()`: called by router guard if not logged in → calls `supabase.auth.getSession()`
- `login(email, password)`: calls `supabase.auth.signInWithPassword()`, fetches profile
- `logout()`: calls `supabase.auth.signOut()`, clears school store
- `fetchProfile(id)`: queries `users` table, loads school info, loads teacher profile
- Security: inactive users are blocked at fetchProfile time (calls `logout()`)
- `handleAuthEvent(event, newSession)`: reacts to Supabase auth state changes

### Router Guard:
1. Check if route is public → allow
2. Check requiresAuth → redirect to `/login` if not authenticated
3. Check role match → redirect to `/unauthorized` if wrong role
4. Admin guard → redirect to `/admin/academic-years` if no academic year selected

### User → Teacher Connection:
```
auth.users
    ↓ id (cascade delete)
public.users        ← role (super_admin/admin/teacher/librarian), status (active/inactive)
    ↓ user_id (not null, unique)
teachers            ← full_name, gender, dob, phone, degree, address, profile_url
    ↓ id
classes             ← teacher_id → which teacher owns which class
    ↓ id
students            ← class_id → which class each student belongs to
```

## 10. Database Schema (v10)

### Enums:
```sql
user_status: 'active', 'inactive'
user_role: 'super_admin', 'admin', 'teacher', 'librarian'
attendance_status: 'present', 'absent', 'late', 'permission'
score_type: 'monthly', 'semester'
budget_type: 'income', 'expense'
borrow_status: 'borrowed', 'returned', 'overdue'
class_turn: 'morning', 'afternoon'
academic_status: 'active', 'inactive'
```

### Core Tables:

**schools** — One row per school. Created by super_admin only.
- `id` uuid PK, `name_khmer` text NOT NULL, `name_english` text, `school_code` text UNIQUE NOT NULL
- `province`, `district`, `address`, `phone`, `email`, `logo_url`, `status`
- RLS: super_admin full access, admin read own

**users** — Linked to auth.users. Role = access level, not identity.
- `id` uuid PK → auth.users(id) CASCADE, `email` NOT NULL, `role` user_role DEFAULT 'teacher'
- `status` user_status DEFAULT 'active', `school_id` → schools(id)
- RLS: super_admin full, admin manage own school, self read

**school_settings** — One per school. Morning/evening start times + late thresholds.
- Auto-created when school is created via `super_admin_create_school()`

**school_information** — Detailed school profile.
- v10 adds: `signature_url` (principal digital signature), `stamp_url` (school stamp)
- Stored in `school-assets` storage bucket (public read, admin write)

**academic_years** — Per-school, year_name, start_date, end_date, status

**subjects** — Global pool per school (e.g., ភាសាខ្មែរ, គណិតវិទ្យា, etc.)

**teachers** — Profile for ALL staff. `user_id` UNIQUE NOT NULL.
- `full_name`, `gender`, `dob`, `phone_number`, `degree`, `address`, `email`, `profile_url`

**classes** — Per school + academic year. Has `teacher_id`, `turn` (morning/afternoon).
- `class_name` (e.g., ថ្នាក់ទី១ក)

**class_subjects** — Junction: which subjects does each class have?
- `unique(class_id, subject_id)`

**students** — Core student data.
- `class_id`, `academic_year_id`, `is_graduated` (for grade 6 → true on rollover)
- `real_id`, `full_name`, `gender`, `dob`, parent info, `is_scholarship`, `is_disability`

**attendances** — Daily student attendance.
- `student_id`, `date`, `status`, `reason`
- Anon: read only via report link context

**scores** — Raw subject scores per student.
- `student_id`, `subject_id`, `academic_year_id`, `score_type` (monthly/semester), `score`, `month`, `semester`
- Anon: read only via report link context

**teacher_attendances** — One row per teacher per day.
- `teacher_id`, `date` (UNIQUE), `check_in_time`, `status`, `note`
- Write only via `teacher_check_in()` function (security definer)
- Admin override via `admin_override_teacher_attendance()` function

**school_holidays** — Per school + academic year. Name, start_date, end_date.

**books** — Library books. `title`, `author`, `isbn`, `category`, `total_copies`, `available_copies`

**book_borrows** — Library borrows. `book_id`, `student_id`, `borrow_date`, `due_date`, `return_date`, `status`

**budget_transactions** — `type` (income/expense), `date`, `description`, `category`, `amount`, `note`

**inventory_items** — `name`, `category`, `quantity`, `min_stock`, `location`, `condition`

**report_links** (v9) — One row per class per month/semester.
- `id` uuid PK (the shareable token)
- v10 adds: `status` (pending/approved/rejected), `rejection_note`, `approved_at`, `approved_by`
- Anon: read only approved links (v10 policy)

**report_messages** (v9) — One row per student per report link.
- `teacher_text`, `teacher_voice_url`, `parent_text`, `parent_voice_url`
- `unique(report_link_id, student_id)`

**notifications** (v10) — In-app notifications.
- `recipient_user_id`, `type` (approval_requested/approval_approved/approval_rejected), `payload` (jsonb), `is_read`
- Created by DB triggers, not directly from frontend

**teacher_phrases** (v10) — Personal feedback phrases per teacher.
- `teacher_id`, `phrase_text`, `sort_order`
- Private per teacher (RLS scoped to own teacher_id)

### Storage Buckets:
- `teacher-profiles` — Profile photos (public read)
- `report-voices` — Voice messages as `.webm` (public read, teacher full, anon parent upload)
- `school-assets` (v10) — Signature + stamp images (public read, admin write)

### Key DB Functions:
- `get_user_role()` — returns role of current user
- `get_user_school_id()` — returns school_id of current user
- `teacher_check_in()` — once-per-day check-in, auto-calc present/late
- `admin_override_teacher_attendance()` — admin can set any teacher's attendance
- `perform_student_rollup()` — end-of-year promotion (grades 1-5 promoted, grade 6 graduated)
- `super_admin_create_school()` — creates school + default settings + info rows
- `notify_admin_on_request()` (trigger) — on INSERT report_links with pending status
- `notify_teacher_on_approval()` (trigger) — on UPDATE report_links.status to approved/rejected

### Key Indexes:
25+ indexes — all tables indexed by `school_id`, plus composite indexes for common queries (student_id+date, student_id+subject_id, etc.)

## 11. Report Link Approval Flow (Detail)

### How it works:

**Teacher side (`/teacher/scores/report-link`):**
1. Teacher selects period (monthly with month picker, or semester with semester picker)
2. Page loads current link status from `report_links` table
3. Link status bar shows: no link / pending / approved / rejected
4. Student cards display each student's scores + attendance summary
5. Teacher writes per-student notes using inline textarea + PhrasePicker chips
6. Notes are saved per-student via upsert into `report_messages`
7. "Send for Approval" button appears when: no link exists, or link is rejected
8. Clicking creates a `report_links` row with `status = 'pending'`
9. Once approved, "Copy Link" button appears — copies `/parent/report/:id` to clipboard
10. Teacher can navigate to report-replies view to see parent replies

**Admin side (`/admin/approvals`):**
1. Admin sees list of pending approval requests
2. Each shows: class name, score type, month/semester
3. Admin can click "Preview" to see the full report
4. Admin can Approve (sets status='approved', approved_at=now(), approved_by=admin's teacher_id)
5. Or Reject with optional note (sets status='rejected', rejection_note=text)

**Notifications:**
- When teacher creates pending link → trigger inserts notification for ALL admins in the school
- When admin approves/rejects → trigger inserts notification for the requesting teacher
- Frontend subscribes to INSERT via Supabase Realtime
- Bell icon in both admin and teacher topbars shows unread count badge

**Parent side:**
- Opens `/parent/report/:report_link_id` → sees dropdown of students in that class
- Selects student → sees report card with scores + attendance + teacher message (text/voice)
- Parent can reply with text or voice
- Footer displays principal signature + school stamp (if configured in admin settings)
- RLS: anon can only read report_links WHERE status = 'approved'

## 12. Score Calculation

**File:** `src/utils/scoreCalculator.js`

### computeMonthlyAverage(scores):
- Filters valid scores (not null, not undefined, not empty string)
- Sums them, divides by count
- Returns `Number((sum / count).toFixed(2))`

### computeSemesterAverage(monthlyAverages, examAverage):
- Averages the valid monthly averages
- Averages that result with the exam average
- Returns `Number(((monthlyAvg + examAvg) / 2).toFixed(2))`

### computeRank(students):
- Competition ranking (1,1,3,4,5,6,6,8)
- Sorts by average descending
- Tracks rank as a closure variable:
  - If current average !== previous average → rank = i + 1
  - Else → rank stays same (tied)
- Returns new objects with `{ ...student, rank }`

### Grade Mapping:
- A: >= 9.0, B: >= 8.0, C: >= 7.0, D: >= 6.0, E: >= 5.0, F: < 5.0

```js
        expiration: { maxEntries: 100, maxAgeSeconds: 86400 },
        networkTimeoutSeconds: 5
      }
    }]
  }
})
```

Composable `usePwa.js` handles:

## 17. Student Rollup

DB function `perform_student_rollup(p_old_year_id, p_new_year_id)`:
1. For grades 1-5: moves students from old-year classes to new-year classes
2. Matches classes by grade (extracted from class_name via `extract_grade_from_class_name`)
3. Handles class count mismatch (multiple old classes → single new class)
4. Grade 6: sets `is_graduated = true`, `class_id = null`
5. Helper functions: `khmer_to_int`, `extract_grade_from_class_name` in frontend utils

Frontend UI in AcademicYearsView: admin clicks "Rollup" button → confirmation modal → calls function via Supabase RPC → shows result summary.

## 20. Edge Function: manage-user

The `manage-user` Supabase Edge Function handles user creation (since auth.users can only be created server-side via Service Role key).

**Payload:**
```json
{
  "action": "create",
  "payload": {
    "email": "user@school.com",
    "password": "securepass",
    "role": "teacher",
    "full_name": "User Full Name",
    "school_id": "uuid-of-school"
  }
}
```

The function:
1. Creates user in `auth.users` with email + password
2. Creates row in `public.users` with role + school_id
3. Creates row in `teachers` with full_name + school_id

## 23. File Reference: Key Implementation Details

### `src/views/teacher/ReportLinkView.vue`
The dedicated report link management page. Features:

- Fetch current link status via `fetchCurrentLink()` — uses `.is('month', null)` for null columns (not `.eq()`)
- Student cards with: name, avatar, average score, attendance count, teacher note textarea + PhrasePicker
- Save teacher note per student via upsert to `report_messages(report_link_id, student_id)`
- Send for approval: calls `fetchCurrentLink()` first to prevent duplicates, then creates/re-submits
- Copy link button: only enabled when `currentLink.status === 'approved'`
- Toast notifications for all actions

### `src/views/teacher/ReportRepliesView.vue`
Parent replies inbox (read-only). Shows:
- Mode selector (monthly/semester)
- Period selector
- Student cards with teacher's original message (text + voice player)
- Parent reply (text + voice player) — read-only, no reply composition
- No PhrasePicker — teacher notes are managed in ReportLinkView instead

### `src/views/teacher/ScoresRankingView.vue`
Ranking page. Shows:
- Mode/period selectors
- Summary stat tiles (total, passed, failed by gender)
- Grade distribution bar
- Score range distribution
- Ranking table with: row number, student name, gender, average with progress bar, grade chip, rank circle
- Buttons: certificate designer, honor board, PDF export, navigation to report-link page
- Competition ranking (1,1,3,4,5,6,6,8) via `computeRank()`

### `src/views/admin/ApprovalsView.vue`
Approval queue for admin. Lists pending report links with approve/reject actions.
Preview link navigates to `AdminReportPreviewView` showing the full report.

### `src/components/report/PhrasePicker.vue`
Reusable component for teacher phrase library.
- Fetches phrases from `teacher_phrases` table scoped to current teacher
- Displays as clickable chips below textarea
- Click appends phrase to current input text
- Teacher can add new phrase inline or delete existing ones
- Emits `@select(phraseText)` event

### `src/components/shared/NotificationsDropdown.vue`
Bell icon component with:
- Unread count badge (red circle with count)
- Dropdown list of recent notifications
- Each notification shows type icon + message + time
- "Mark all as read" button
- Highlights approval_requested as warning, approval_approved as success, approval_rejected as danger
- Realtime subscription: new notifications appear instantly
