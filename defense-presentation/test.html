Primary School Management System

A Multi-Tenant SaaS Platform for Cambodian Primary Schools

Problem Statement

  • Paper-based record keeping across all school operations — enrollment, attendance, scores, health
  • No dedicated software budget in Cambodian public primary schools
  • Student health, attendance, and academic performance tracked in separate, disconnected systems
  • Report card generation is entirely manual — error-prone and time-consuming for teachers
  • No secure, practical mechanism to share student progress with parents

Objectives & Scope

  • Design a multi-tenant SaaS platform — one codebase serving unlimited schools
  • Digitize student records: enrollment, attendance, scores, health, and growth tracking
  • Enable secure, login-free parent access to report cards via private links
  • Support 5 distinct user roles with appropriate access boundaries
  • Deliver a bilingual Khmer/English interface with PWA offline capability
  • Provide teachers with a reusable phrase library for parent communication

Why Existing Solutions Don't Fit

  • Excel spreadsheets — no multi-tenancy, no access control, no parent sharing, single-user
  • Paper records — slow, error-prone, no backup, impossible to aggregate data across schools
  • Generic SIS software (Schoology, PowerSchool) — expensive licensing, English-only, requires reliable internet, not designed for Cambodian school structures
  • Per-school custom builds — no economies of scale, each deployment is isolated and costly
The gap: No solution that is free, bilingual, offline-capable, and multi-tenant by design.

Security Model — RLS Layers

Super Admin
Cross-school platform access — manages all tenants
Admin / Director
Full access within their school_id — approves reports, manages staff
Teacher / Librarian
Access scoped to assigned classes or library within their school
Parent (Anonymous)
No login — access strictly limited to a single approved report UUID link
Parents never touch the authentication system. Even anonymous access is gated by database-level RLS policies.

Feature: Parent Portal

  • Parents access their child's report card via a private UUID link — no login required
  • No name search, no date-of-birth verification — just the link, nothing else
  • Shown: academic scores and attendance records only
  • Hidden by design: health records, growth measurements, vaccination history — visible to staff only
  • Link is single-purpose, revocable, and scoped to one approved report card
Privacy by design — the link reveals only what a parent needs to see, nothing more.

Challenges & Solutions

Khmer Digit Parsing for Grade Rollups
Class names like ថ្នាក់ទី១ក use Khmer numerals — standard parseInt() returns NaN.
Solution: Custom parser mapping Khmer digits (០–៩) to Arabic (0–9), enabling automated end-of-year grade promotion.
RLS for Anonymous Multi-Step Parent Access
Parents have no auth token — how do you enforce RLS on an unauthenticated request?
Solution: A report_links table with UUID, expiration, and approved flag. RLS policy validates the UUID against this table before returning any data.
Bilingual UI with Asymmetric Text Lengths
Khmer and English labels differ significantly in length — fixed-width layouts break.
Solution: Tailwind's responsive utilities combined with per-language string management and flexible containers.
