## 🧠 Core Design Decisions

### Every User IS a Teacher

In Cambodian schools, all staff members are teachers. The librarian is a teacher who manages the library. The admin/director is a teacher who runs the school. Therefore:

- **Every user account** always has a matching `teachers` row (personal profile)
- The `role` field in `public.users` only controls **what they can access** in the app — not who they are
- There is no such thing as a user without a teacher profile
- `teachers.user_id` is `NOT NULL UNIQUE` — one profile per account, always linked

### User → Teacher Connection

```
auth.users
    ↓ id (cascade delete)
public.users        ← role (super_admin/admin/teacher/librarian), status (active/inactive)
    ↓ user_id (not null, unique)
teachers            ← full_name, gender, dob, phone, degree, address, profile_url
    ↓ id
classes             ← teacher_id → which teacher owns which class
    ↓ id
students            ← class_id → which student belongs to which class
```

### Parent Portal — Link-Only Entry (v9)

Parents no longer search by name + DOB. Access is granted exclusively via a report link generated by the teacher:

- Teacher generates one link per class per month/semester from the **Score Ranking page**
- Link is a UUID-based URL: `/parent/report/:report_link_id`
- Parent opens link → sees a dropdown of all students in that class → selects their child
- Report card shows scores + attendance for that specific month/period only
- Health, growth, vaccinations, sick days are **not exposed** — private to staff only
- Teacher can leave a text or voice message per student
- Parent can reply with text or voice per student
- Anon RLS is scoped to `report_link_id` — no open `using (true)` policies

### Report Link Approval Flow (v10)

Before a teacher can share a parent report link, the principal (admin) must approve it:

- Teacher clicks **"Request Approval"** on `/teacher/scores/ranking` → `report_links.status` set to `pending`
- Admin receives an **in-app notification** (bell icon in topbar) with unread count badge
- Admin opens notification → reviews the request → clicks **Approve** or **Reject** (with optional rejection note)
- Teacher receives an in-app notification of the decision
- If approved → **"Share Link"** button unlocks for the teacher
- If rejected → teacher sees the rejection note and can revise/re-request
- Parent report card footer displays the **principal's digital signature image + school stamp image**
- Signature and stamp images are uploaded by admin in **Settings → School Information**

### Teacher Phrase Library (v10)

Teachers maintain a personal library of reusable feedback phrases for student messages:

- Each teacher owns their own phrases — private, not shared across teachers
- When composing a student message (in report-replies), saved phrases appear as **clickable chips** below the message box
- Clicking a chip **appends** the phrase to the current message text
- Teacher can add a new phrase inline and delete existing ones
- Phrases persist across classes, months, and academic years
- Completely optional — message box works normally without any saved phrases

### Offline-First Architecture (v17)

Teachers in rural Cambodia face unreliable internet. The app now supports offline writes with automatic sync, scoped to score entry only:

- Connection status detected via `navigator.onLine` + browser events — banner + sync **teacher-only**
- Yellow banner at page top when offline (dismissible, shows pending count)
- Write operations (upsert) intercepted when offline → queued to localStorage
- Auto-sync on reconnect: queue processed in FIFO order, success/failure toasts
- Currently applied to **monthly + semester score entry** only
- Single global toast container — no more duplicate toast implementations across views
- Storage assets (profile pics, signatures, stamps, voice) cached via CacheFirst strategy

## 📌 Notes

- Supabase anon key is safe to expose in frontend (RLS protects data)
- Parent portal uses Supabase anon role — no login required, link-scoped only
- **Anon users cannot access `pending` or `rejected` report links**
- Score calculations happen on the frontend (`scoreCalculator.js`) — DB stores raw scores only
- Rank computed within class only — ties share rank, next rank skips (1,1,3...)
- Subjects are per-class — fetched from `class_subjects`, not global `subjects`
- Grade 1-3 no English · Grade 4-6 includes English
- Cambodia school days = **Monday to Saturday** — Sundays off by default
- `manage-user` Edge Function always creates 3 rows: `auth.users` + `public.users` + `teachers`
- Voice messages stored as `.webm` in `report-voices` bucket
- Offline queue uses localStorage — persists across page reloads, cleared on successful sync
- Queue operations are FIFO — order of writes is preserved during sync
- `useOfflineMutation` returns `{ queued: true }` when offline — views can use this to show offline-specific feedback

### Session 4 — Auth Session Persistence Fix (July 2026)

**Problem:** PWA users had to re-login after closing and reopening the app. The `INITIAL_SESSION` auth event (fired on startup to restore the session from localStorage) was completely skipped by `handleAuthEvent`, relying solely on `init()` in the router guard. Async timing gaps could leave `session.value` null.

**Fix in `src/stores/auth.js`:**
- `handleAuthEvent` no longer skips `INITIAL_SESSION` — sets `session.value` and calls `fetchProfile()` immediately when the listener fires, instead of deferring to `init()`
- `init()` now bails early with `if (session.value) return` — avoids duplicate `fetchProfile()` if `handleAuthEvent` already restored the session
- Two redundant session-restore paths ensure the user stays logged in across PWA restarts
