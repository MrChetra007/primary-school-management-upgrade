> **Stack:** Vue 3 + Vite + Tailwind CSS + Supabase
> **Roles:** Admin/Director · Teacher · Librarian · Parent (anon, link-only)

---

## 🧠 Core Design Decisions

### Every User IS a Teacher

In Cambodian schools, all staff members are teachers. The librarian is a teacher who manages the library. The admin/director is a teacher who runs the school. Therefore:

- **Every user account** always has a matching `teachers` row (personal profile)
- The `role` field in `public.users` only controls **what they can access** in the app — not who they are
- There is no such thing as a user without a teacher profile
- `teachers.user_id` is `NOT NULL UNIQUE` — one profile per account, always linked

### User → Teacher Connection

```
auth.users
    ↓ id (cascade delete)
public.users        ← role (admin/teacher/librarian), status (active/inactive)
    ↓ user_id (not null, unique)
teachers            ← full_name, gender, dob, phone, degree, address, profile_url
    ↓ id
classes             ← teacher_id → which teacher owns which class
    ↓ id
students            ← class_id → which class each student belongs to
```

### Parent Portal — Link-Only Entry (v9)

Parents no longer search by name + DOB. Access is granted exclusively via a report link generated by the teacher:

- Teacher generates one link per class per month/semester from the **Score Ranking page**
- Link is a UUID-based URL: `/parent/report/:report_link_id`
- Parent opens link → sees a dropdown of all students in that class → selects their child
- Report card shows scores + attendance for that specific month/period only
- Health, growth, vaccinations, sick days are **not exposed** — private to staff only
- Teacher can leave a text or voice message per student
- Parent can reply with text or voice per student
- Anon RLS is scoped to `report_link_id` — no open `using (true)` policies

## 🗄️ Data Model Overview (v9)

### New Tables (v9)

#### `report_links`

One row per class per month/semester. Generated by teacher from the ranking page. UUID is the shareable link token.

| Column             | Type                  | Notes                                                                              |
| ------------------ | --------------------- | ---------------------------------------------------------------------------------- |
| `id`               | uuid PK               | The shareable token — used as the URL param                                        |
| `school_id`        | uuid → schools        | Multi-tenant scope                                                                 |
| `class_id`         | uuid → classes        | Which class this report covers                                                     |
| `academic_year_id` | uuid → academic_years | Which year                                                                         |
| `created_by`       | uuid → teachers       | Teacher who generated the link                                                     |
| `score_type`       | score_type            | `monthly` or `semester`                                                            |
| `month`            | int2                  | 1–12, null if semester                                                             |
| `semester`         | int2                  | 1 or 2, null if monthly                                                            |
| `created_at`       | timestamptz           |                                                                                    |
| **unique**         |                       | `(class_id, academic_year_id, score_type, month, semester)` — one link per context |

#### `report_messages`

One row per student per report link. Holds teacher message + parent reply (text + voice).

| Column              | Type                | Notes                          |
| ------------------- | ------------------- | ------------------------------ |
| `id`                | uuid PK             |                                |
| `school_id`         | uuid → schools      |                                |
| `report_link_id`    | uuid → report_links |                                |
| `student_id`        | uuid → students     |                                |
| `teacher_text`      | text                | Teacher's written message      |
| `teacher_voice_url` | text                | Supabase Storage URL           |
| `parent_text`       | text                | Parent's written reply         |
| `parent_voice_url`  | text                | Supabase Storage URL           |
| `created_at`        | timestamptz         |                                |
| `updated_at`        | timestamptz         |                                |
| **unique**          |                     | `(report_link_id, student_id)` |

### New Storage Bucket (v9)

```
report-voices/
  {report_link_id}/{student_id}/teacher.webm
  {report_link_id}/{student_id}/parent.webm
```

Policies:

- Teacher: full access to their own report link's folder (authenticated)
- Anon: insert + update to `parent.webm` path only
- Public read: all files in bucket

### RLS Changes (v9)

| Table                  | Change                                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `students`             | Anon policy tightened — `class_id in (select class_id from report_links where id = :link_id)` instead of `using (true)` |
| `scores`               | Same tightening — scoped to report link's class                                                                         |
| `attendances`          | Same tightening — scoped to report link's class                                                                         |
| `student_health`       | Anon policy **removed** — health is private                                                                             |
| `student_checkups`     | Anon policy **removed**                                                                                                 |
| `student_growth`       | Anon policy **removed**                                                                                                 |
| `student_vaccinations` | Anon policy **removed**                                                                                                 |
| `student_sick_days`    | Anon policy **removed**                                                                                                 |
| `report_links`         | New — teacher manages own, anon can read by id                                                                          |
| `report_messages`      | New — teacher manages, anon can read + update parent fields by report_link_id                                           |

> **Note on anon UPDATE for parent fields:** The anon update policy on `report_messages` allows writing `parent_text` and `parent_voice_url`. The policy uses `with check` to ensure the row's `report_link_id` matches a valid link. Teacher-owned fields (`teacher_text`, `teacher_voice_url`) can only be written by authenticated users. A determined user hitting the API directly could attempt to overwrite any field — mitigate by having the frontend never send teacher fields on parent update, and accept this as an acceptable trust boundary for the anon role.

## 🧩 Teacher Flow — Read Parent Replies

1. Teacher navigates to `/teacher/scores/report-replies`
2. Page loads all `report_links` created by this teacher for their class
3. Teacher selects score type (monthly / semester) → then selects month (or semester number)
4. Page fetches all `report_messages` for the matching `report_link_id`
5. Displays a list of all students in the class with reply status:
   - **Replied** — parent has submitted `parent_text` or `parent_voice_url`
   - **No reply yet** — `report_messages` row missing or both parent fields null
6. For each student who replied:
   - Show `parent_text` (read-only)
   - Show audio player for `parent_voice_url` if set
   - Show date of last update (`updated_at`)
7. Teacher cannot edit parent replies — read-only inbox

**Key query (authenticated teacher):**

```js
// Step 1: find the report_link for selected context
const { data: link } = await supabase
  .from("report_links")
  .select("id, class_id")
  .eq("school_id", schoolStore.schoolId)
  .eq("academic_year_id", academicYearStore.academicYearId)
  .eq("created_by", teacherId)
  .eq("score_type", selectedScoreType)
  .eq("month", selectedMonth ?? null) // null if semester
  .eq("semester", selectedSemester ?? null) // null if monthly
  .maybeSingle();

// Step 2: fetch all messages + student names for that link
const { data: messages } = await supabase
  .from("report_messages")
  .select("*, students(full_name, gender)")
  .eq("report_link_id", link.id)
  .order("students(full_name)");

// Step 3: fetch all students in class to show "no reply yet" rows
const { data: allStudents } = await supabase
  .from("students")
  .select("id, full_name, gender")
  .eq("class_id", link.class_id)
  .eq("is_graduated", false)
  .order("full_name");
```

## 🧩 Parent Flow — Report Card

1. Parent opens link `/parent/report/:report_link_id`
2. App fetches `report_links` row by id (anon, public read)
3. Fetches all students in that `class_id` (anon, scoped to link's class)
4. Shows dropdown: "Select your child"
5. Parent selects → navigates to `/parent/report/:report_link_id/:student_id`
6. Report card loads:
   - Student name + class
   - Scores for that month/semester (from `scores` table, scoped)
   - Attendance for that month (from `attendances` table, scoped)
   - Teacher message: text (if any) + voice player (if any)
   - Parent reply section: text input + voice recorder → uploads `.webm` to Storage → saves URL to `report_messages`

## 🔊 Voice Messaging

## 📌 Notes

- Supabase anon key is safe to expose in frontend (RLS protects data)
- Parent portal uses Supabase anon role — no login required, link-scoped only
- Score calculations happen on the frontend (`scoreCalculator.js`) — DB stores raw scores only
- Rank computed within class only — ties share rank, next rank skips (1,1,3...)
- **Student rollup parses grade from class name** — requires consistent `ថ្នាក់ទី{Khmer digit}{letter}` naming
- Rollup updates `class_id` + `academic_year_id` in-place — no data duplication
- Grade 6 graduates: `is_graduated = true`, `class_id = null`
- **Subjects are per-class** — fetched from `class_subjects`, not global `subjects`
- Grade 1-3 no English · Grade 4-6 includes English
- All file uploads → Supabase Storage, only URLs in DB
- **Every user has a teachers profile** — role only controls access, not identity
- **Multi-tenant (v8):** every query auto-scoped by `school_id` via RLS — no manual filtering needed in frontend
- **Super admin** (Tra only) — bypasses all school RLS, sees all data across all schools
- `get_user_school_id()` helper function used in all RLS policies for school scoping
- `super_admin_create_school()` auto-creates `school_settings` + `school_information` rows for new school
- `manage-user` Edge Function now requires `school_id` in payload for user creation
- 25+ indexes added in v8 migration for multi-tenant performance at scale
- Cambodia school days = **Monday to Saturday** — Sundays off by default
- `manage-user` Edge Function always creates 3 rows: `auth.users` + `public.users` + `teachers`
- **Parent portal (v9):** access via report link only — no search, no DOB, no direct student URL
- **Report link** is generated from `/teacher/scores/ranking` — upsert is idempotent (unique constraint)
- **Anon RLS (v9):** students/scores/attendances scoped to `class_id` from `report_links` — not open
- **Health data (v9):** all anon policies removed from health/growth/vaccinations/sick_days — staff only
- **Voice messages:** stored as `.webm` in `report-voices` bucket — teacher and parent each have one file per student per report
- Potential partnerships: MoEYS, UNICEF Cambodia, World Bank, Room to Read, Aide et Action
