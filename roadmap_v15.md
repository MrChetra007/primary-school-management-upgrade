## 🧠 Core Design Decisions

### Every User IS a Teacher

In Cambodian schools, all staff members are teachers. The librarian is a teacher who manages the library. The admin/director is a teacher who runs the school. Therefore:

- **Every user account** always has a matching `teachers` row (personal profile)
- The `role` field in `public.users` only controls **what they can access** in the app — not who they are
- There is no such thing as a user without a teacher profile
- `teachers.user_id` is `NOT NULL UNIQUE` — one profile per account, always linked

### User → Teacher Connection

```
auth.users
    ↓ id (cascade delete)
public.users        ← role (super_admin/admin/teacher/librarian), status (active/inactive)
    ↓ user_id (not null, unique)
teachers            ← full_name, gender, dob, phone, degree, address, profile_url
    ↓ id
classes             ← teacher_id → which teacher owns which class
    ↓ id
students            ← class_id → which class each student belongs to
```

### Parent Portal — Link-Only Entry (v9)

Parents no longer search by name + DOB. Access is granted exclusively via a report link generated by the teacher:

- Teacher generates one link per class per month/semester from the **Score Ranking page**
- Link is a UUID-based URL: `/parent/report/:report_link_id`
- Parent opens link → sees a dropdown of all students in that class → selects their child
- Report card shows scores + attendance for that specific month/period only
- Health, growth, vaccinations, sick days are **not exposed** — private to staff only
- Teacher can leave a text or voice message per student
- Parent can reply with text or voice per student
- Anon RLS is scoped to `report_link_id` — no open `using (true)` policies

## 🗄️ Schema & Data Model (v9)

### Core Tables

| Table                  | Purpose                                              |
| ---------------------- | ---------------------------------------------------- |
| `schools`              | Multi-tenant: one row per school                     |
| `users`                | Linked to `auth.users`; `school_id` scopes tenant    |
| `teachers`             | Profile for ALL staff (admin/teacher/librarian)      |
| `school_settings`      | Late thresholds, shift times per school              |
| `school_information`   | School profile (name, logo, director, address)       |
| `academic_years`       | Per-school academic years                            |
| `subjects`             | Global subject pool per school                       |
| `classes`              | Per-school + per-year, assigned teacher + turn       |
| `class_subjects`       | Junction: which subjects does each class have        |
| `students`             | Core student data, scoped to class + year            |
| `student_health`       | Static health profile (staff only)                   |
| `student_checkups`     | Periodic health visits (staff only)                  |
| `student_growth`       | Height/weight records (staff only)                   |
| `student_vaccinations` | Vaccination records (staff only)                     |
| `student_sick_days`    | Sick day records (staff only)                        |
| `attendances`          | Daily student attendance (anon scoped to report link)|
| `scores`               | Raw subject scores per student (anon scoped)         |
| `teacher_attendances`  | Teacher check-in (once-per-day, auto-calc late)      |
| `school_holidays`      | Off days shaded in attendance calendars              |
| `books`                | Library books                                        |
| `book_borrows`         | Book borrow records                                  |
| `budget_transactions`  | Income/expense tracking                              |
| `inventory_items`      | School inventory                                     |
| `report_links`         | **v9** UUID tokens per class per month/semester     |
| `report_messages`      | **v9** Teacher message + parent reply per student   |

### Storage Buckets

| Bucket              | Purpose                                      |
| ------------------- | -------------------------------------------- |
| `teacher-profiles`  | Staff profile pictures (public read)         |
| `report-voices`     | **v9** Teacher/parent voice `.webm` files    |

### Key Indexes
- 25+ indexes for multi-tenant performance (all tables indexed by `school_id`)
- Composite indexes on attendance, scores, report_links for common queries

## 📌 Notes

- Supabase anon key is safe to expose in frontend (RLS protects data)
- Parent portal uses Supabase anon role — no login required, link-scoped only
- Score calculations happen on the frontend (`scoreCalculator.js`) — DB stores raw scores only
- Rank computed within class only — ties share rank, next rank skips (1,1,3...)
- Student rollup parses grade from class name — requires consistent `ថ្នាក់ទី{Khmer digit}{letter}` naming
- Grade 6 graduates: `is_graduated = true`, `class_id = null`
- Subjects are per-class — fetched from `class_subjects`, not global `subjects`
- Grade 1-3 no English · Grade 4-6 includes English
- Cambodia school days = **Monday to Saturday** — Sundays off by default
- `manage-user` Edge Function always creates 3 rows: `auth.users` + `public.users` + `teachers`
- Voice messages stored as `.webm` in `report-voices` bucket
- Potential partnerships: MoEYS, UNICEF Cambodia, World Bank, Room to Read, Aide et Action
